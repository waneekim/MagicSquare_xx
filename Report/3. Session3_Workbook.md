## 1) 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

> **빈칸 2개를 채운 4×4 격자에서, 행·열·대각선 판정을 빠뜨리지 않고 틀린 '완료' 상태를 붙잡는 시간을 줄인다.**

- Pain(판정 누락·재확인 비용) 중심. "검증 프로그램을 만든다"는 표현은 넣지 않음.

---

## 2) R-G-I-O

| | 내용 |
|---|------|
| **Role** | 부분 마방진 담당자 — 4×4 격자(빈칸 2개)를 채우고 **행·열·대각선 합 34**, **1~16 중복 없음**을 만족하는지 확인해야 하는 학습자 |
| **Goal** | 빈칸 2개를 채운 격자가 **마방진 조건 전체**를 만족하는지 **확실히 판정**하고, 틀린 줄(행·열·대각선)을 빨리 찾아 **불필요한 재작업 시간**을 줄인다 |
| **Input** | 4×4 정수 격자. `0` = 빈칸 2개, 나머지는 1~16 (중복·범위 위반 가능) |
| **Output** | 조건 충족 여부 + 실패 시 **어느 줄이 틀렸는지**(행/열/대각선) 또는 빈칸이 채워진 완성 격자 |

---

## 3) 성공 기준 3개 (Mom Test 증거와 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| **SC1** | 행 4개·열 4개·**대각선 2개** 합이 모두 34인지 **한 번에** 검사한다 (대각선 누락 없음) | ② "행열 대각선 합을 맞췄는데" → **대각선까지 포함한 전체 판정** |
| **SC2** | 빈칸 2개를 채운 완성 격자에 대해 **1~16 중복·범위**까지 검사해, "거의 맞다" 상태를 **완료로 오인하지 않는다** | ① "빈칸 2개 넣고" → **채운 직후의 판정 정확도** |
| **SC3** | 검증 테스트가 통과하면, 손으로 줄마다 다시 세지 않고 **맞다고 확신**할 수 있다 (재확인·디버깅 시간 감소) | ③ "대각선 하나를 빼먹어서 20분 날렸다" → **확인·재작업 비용** 감소 |

## 4) 표면 문제 — 이번 프로젝트에서 **하지 않을 것**

> 표면 정의: *"4×4 부분 마방진용 **검증 프로그램을 만들면**, 행·열·대각선 합을 자동으로 확인할 수 있다."*

| 하지 않을 것 | 이유 (Mom Test) |
|--------------|-----------------|
| **"검증 앱·자동 Solver"를 목표로 삼는 것** | 진짜 pain은 도구 부재가 아니라 **판정 누락(대각선)·틀린 완료 확신·20분 낭비** |
| **행·열만 맞으면 통과**로 두는 것 | 증거 ②③ — 대각선 빠뜨림이 핵심 실패 조건 |
| **힌트·풀이 공유·UI 격자 편집기**를 SC1~3 전에 우선 | Mom Test 미검증 가설(포기·공유 의향) — **범위 밖** |
| **ECB 전체**(MissingFinder, Solver, CLI)를 세션 3에 한꺼번에 구현 | 이번 세션은 **Rule·Command·(Skill)·Test Loop** 인프라만 |
| **"만들면 좋겠다" 수준** 기능만 늘리는 것 | 과거 행동·비용 증거 없는 항목은 Won't |

## 8계층 — 이번 세션에서 만드는 것

> 세션 3 범위: **Rule, Command, (Skill), Test Loop** 만.  
> (Prompt / Hook / Subagent / MCP 등은 후속 세션)

### Rule (규칙)

```text
- Mom Test 진짜 문제: "대각선 누락 → 틀린 완료 확신 → 시간 낭비"를 줄이는 것이 1순위다.
- 도메인: 4×4, 빈칸 0은 2개, 채운 값은 1~16, 마방진 합 = 34.
- 검증 범위: 행 4 + 열 4 + 대각선 2 + 1~16 중복·범위 (대각선 생략 금지).
- 설계 방향: ECB — MagicSquare, Cell, SquareValidator (세션 후반 확장: MissingFinder, Solver).
- 구현 전·후: SquareValidator 동작을 테스트로 고정한다 (TDD).
- AI 프롬프트: 솔루션 제안보다 "어느 줄을 빠뜨렸는지" 불편·비용으로 되돌린다 (Mom Test 리마인더).
```

### Command (명령)

```text
# Mom Test 인터뷰 (세션 1~2 산출)
# Prompt/MomTest_인터뷰.md 참고 — 질문 1개씩, 솔루션 금지

# 테스트 (예시 — 프로젝트 스캐폴딩 후)
pytest
# 또는
python -m pytest tests/

# 검증 대상 예시 입력
# 4×4 grid, 0 = missing, 1~16 filled
```

### Skill (선택 — AI 활용 시)

```text
- TDD: Red(실패 TC) → Green(SquareValidator 최소 구현) → Refactor(검증 책임 분리).
- Mom Test 리마인더: "이 테스트가 대각선 2개를 반드시 검사하는가?" SC1에 대조.
- ECB: SquareValidator는 검증만; 빈칸 채우기(Solver)는 후속 세션.
- 실패 메시지: "어느 행/열/대각선이 34가 아닌지" 알 수 있게 (재현·디버깅 비용 ↓).
```

### Test Loop (검증 루프)

```text
[Loop 1 — 줄 합 34]  SC1
  RED  : 행·열·대각선 각각 합 34 assert (대각선 2개 TC 필수)
  GREEN: SquareValidator — 10줄 검사 구현
  REF  : 행/열/대각 검사 메서드 분리

[Loop 2 — 값 유효성]  SC2
  RED  : 1~16 범위 밖, 중복, 빈칸 0 남음 → 실패 TC
  GREEN: 값·빈칸 검사 추가
  REF  : Cell / MagicSquare 경계 정리

[Loop 3 — 완성 판정]  SC3
  RED  : 빈칸 2개 채운 "거의 맞음" 격자 vs 진짜 마방진 — 통과/실패 구분 TC
  GREEN: isComplete() 또는 동등 API
  DONE : SC1~3 체크리스트 통과 → 손 재확인 없이 제출 가능
```
